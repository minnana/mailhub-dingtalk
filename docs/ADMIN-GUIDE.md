# 公司邮箱管理员手册

本手册覆盖 Mailhub 钉钉应用 0.1.0 已实现的管理页面和操作。部署目标是 Nextcloud 34.0.5、Mail 5.12.5；文中的 `example.com` 是公开示例域名，必须替换为自己的部署地址。

本手册不构成上线验收报告。配置完整、取得应用访问令牌、证书签发或代码检查通过，都不能单独证明真实员工免登、邮箱收发或钉钉提醒已经成功；这些需要分别实测。

首次安装先按 [新手路线](QUICKSTART.md) 和 [部署手册](DEPLOYMENT.md) 准备服务器，再按本手册第 2 节配置钉钉。已上线系统的日常工作主要是第 4、5 节的员工和通知管理；备份、升级与恢复命令统一放在 [维护手册](OPERATIONS.md)。

## 1. 管理入口与职责

| 入口 | 示例地址 |
| --- | --- |
| 员工钉钉入口 | `https://example.com:18443/index.php/apps/mailhub_dingtalk/` |
| 邮箱管理控制台 | `https://example.com:18443/index.php/apps/mailhub_dingtalk/admin` |
| 管理员本地登录 | `https://example.com:18443/index.php/login` |
| 员工网页登录设置 | `https://example.com:18443/index.php/apps/mailhub_dingtalk/personal`，需要先登录自己的员工账号。 |

使用独立的 Nextcloud 本地管理员账号登录，再进入管理控制台；也可从 Nextcloud 管理设置中的本应用入口进入。未登录的访客和普通员工不能使用管理接口。不要把管理员账号共享给员工。

公司只需发布一个企业内部网页应用，员工各自使用自己的钉钉身份。首次成功免登时建立独立账号，邮箱由员工分别授权，不需要给每个人创建一个钉钉应用。

管理控制台提供配置状态、员工访问控制、邮箱绑定概览和通知状态。服务器安装、证书续期、备份恢复、邮箱服务商策略和 Google OAuth 配置由具备相应权限的管理员处理，控制台没有服务器终端或执行系统命令功能。

## 2. 开放前准备

确认以下事项后再邀请首批员工：

1. HTTPS 入口在公司内网和外网均可访问，证书有效，电脑与手机实际使用的钉钉版本均通过访问测试。
2. 钉钉企业内部应用已添加网页能力，电脑和手机首页配置为员工入口，并发布到试用人员范围。
3. 服务器已经配置正确企业的 CorpId、Client ID、Client Secret 和 AgentId。Client ID/Secret 在旧界面中可能叫 AppKey/AppSecret；开发者 API Token 和群机器人地址不能代替应用密钥。
4. 服务器允许的员工范围与钉钉应用可见范围匹配。默认不向任意人员开放注册，先用少量员工名单试运行。
5. Mail 已启用且版本受支持，后台任务正常运行。准备至少两名员工、各自的邮箱，以及能发出和收到测试邮件的外部地址。
6. 保留独立本地管理员入口，并完成备份和恢复演练。

服务器配置约定见[应用技术说明](../custom_apps/mailhub_dingtalk/README.md)。企业应用密钥只放在服务器受限配置中，不写入公开文档、源代码或前端页面；本控制台也不提供输入或回显密钥的功能。

本方案通过服务器主动调用钉钉完成免登兑换和工作通知，未实现人员事件订阅，不要求为这两个流程额外开放公网 HTTP 事件回调。钉钉开放平台的应用设置与限制应以实际企业后台为准。

### 2.1 确认企业和开发权限

使用有企业开发/应用管理权限的账号进入 [钉钉开发者后台](https://open-dev.dingtalk.com/)，确认当前组织是准备部署邮箱的企业。普通员工没有创建权限时，由企业管理员按 [官方开发者权限说明](https://open.dingtalk.com/document/dingstart/get-developer-permissions) 授权；不要用个人应用、第三方 ISV 应用或群机器人代替企业内部应用。

新建一个应用供全公司使用，员工无需逐人创建应用。若需要多人维护，在该应用的成员管理中添加协同人员；“能在工作台使用应用”和“能修改应用配置”是两种不同权限。

### 2.2 创建应用并记录四类参数

在开发者后台的“应用开发”中选择企业内部的“钉钉应用”，创建应用，填写名称和用途，例如“公司邮箱”“统一访问已授权邮箱并接收个人新邮件提醒”。进入应用详情的“基础信息 → 凭证与基础信息”查看应用凭证。新版界面以“添加应用能力”选择网页应用；旧界面可能直接显示 H5 微应用。[官方创建说明](https://open.dingtalk.com/document/dingstart/create-application)

| 要保存的参数 | 写入 Mailhub 的字段 | 用途及常见误填 |
| --- | --- | --- |
| CorpId | `corp_id` | 当前企业标识；在企业开发信息中确认。不是员工 userId，也不是应用 ID。 |
| Client ID，旧称 AppKey | `client_id` | 当前内部应用的标识，用于客户端取码与服务端应用凭证。 |
| Client Secret，旧称 AppSecret | `client_secret` | 当前应用秘密，只保存在服务器。开发者 API Token、机器人 Token 和 Webhook 都不能替代。 |
| AgentId | `agent_id` | 该企业内部应用的数字标识，用于工作通知和电脑端打开应用；不要填 Client ID。 |

四类参数必须来自同一个企业及其应用。不要把本手册的示例、其他企业参数或个人开发工具的 Token 混入配置。既有员工账号按企业和员工标识映射，已经使用后不要随意改为另一个 CorpId。

### 2.3 添加网页能力和两个首页

在应用详情选择“应用能力 → 添加应用能力 → 网页应用”，再进入网页应用的编辑页。按下面的地址填写；部署域名统一后，不要给手机和电脑写成两套入口。[官方网页配置说明](https://open.dingtalk.com/document/dingstart/configure-web-application)

| 配置项 | 本项目示例 |
| --- | --- |
| 移动端首页地址 | `https://example.com:18443/index.php/apps/mailhub_dingtalk/` |
| PC 端首页地址 | `https://example.com:18443/index.php/apps/mailhub_dingtalk/` |
| 管理后台地址（可选） | `https://example.com:18443/index.php/apps/mailhub_dingtalk/admin` |

两个首页都填，才能让计划使用的电脑和手机都有入口。管理后台地址只指向登录后受管理员权限保护的页面，填写该地址不会给普通员工提升权限。

在“开发配置 → 安全设置”核对端内免登地址/域名设置，使其与运行页面使用同一域名。**完整网址字段应保留 `https://` 和实际 `:18443`；仅要求域名的字段按该字段格式填写主机名，不要把路径塞进域名栏。** 官方免登说明要求首页、相关安全地址与运行 JSAPI 的域名一致；具体安全字段的格式与高端口校验，以当前后台提示和保存后的实际测试为准。[官方免登流程](https://open.dingtalk.com/document/development/enterprise-internal-application-logon-free)

本插件使用 `dd.requestAuthCode` 取得一次性授权码，再由本站后端兑换身份。它没有另外实现一个需要填写到钉钉的网页 OAuth GET 回调接口，不要把插件的 POST `/auth` 当成事件回调网址。当前也不需要配置机器人、事件订阅、回调验签 Token 或 AES Key。

如应用后台配置了服务器出口 IP 白名单，核对服务器访问钉钉 API 时的实际公网出口；这个地址不一定等于网站入站公网地址，更不是服务器内网地址。多出口网络要在实际运行路径上验证，避免应用页面能打开但服务端 API 被拒绝。

当前取码接口官方列出的最低版本为 Android/iOS 7.0.45、Windows/macOS 7.0.50；实际部署应使用仍受支持的钉钉版本，并分别测试所用设备。仅满足版本号不代表免登配置已经通过。[requestAuthCode 官方说明](https://open.dingtalk.com/document/development/jsapi-request-auth-code)

### 2.4 核对实际需要的接口权限

在应用的接口权限管理中，只按本插件实际调用的能力核对。以下三个旧版业务接口的官方文档列出的权限为 `qyapi_base`，显示说明是“调用企业 API 时需要具备的基本权限”；若本企业后台显示该权限已默认开放，无需为此额外申请整本通讯录权限。后台状态或接口返回不符时，按对应接口的当前权限说明处理。

| 实际调用 | 用途 | 官方资料 |
| --- | --- | --- |
| `POST /v1.0/oauth2/accessToken` | 用本应用 Client ID/Secret 获取服务端凭证。 | [获取企业内部应用 accessToken](https://open.dingtalk.com/document/orgapp/obtain-the-access_token-of-an-internal-app) |
| `POST /topapi/v2/user/getuserinfo` | 兑换免登码，确认员工 userId。 | [通过免登码获取用户信息](https://open.dingtalk.com/document/development/obtain-the-userid-of-a-user-by-using-the-log-free) |
| `POST /topapi/message/corpconversation/asyncsend_v2` | 以本应用身份给指定员工发个人工作通知。 | [发送工作通知](https://open.dingtalk.com/document/development/asynchronous-sending-of-enterprise-session-messages) |
| `POST /topapi/message/corpconversation/getsendresult` | 查询通知是否向目标员工投递。 | [获取工作通知发送结果](https://open.dingtalk.com/document/development/gets-the-result-of-sending-messages-asynchronously-to-the-enterprise) |

客户端 `requestAuthCode` 属于网页应用取码能力。当前源码**没有调用查询用户详情、全量通讯录、手机号或部门列表接口**，不应因为别的免登示例用了这些接口就一并申请。通知是应用的个人工作通知，不是群机器人；群聊成员名单和机器人 Webhook 不参与这里的接收人匹配。

同时查看本企业可用的 OpenAPI 调用额度与频率限制。发送、查结果和登录都会产生调用，不能只按通知条数估算用量。不要在公共讨论区贴应用凭证或带 access token 的请求 URL。

### 2.5 写入服务器受限配置

完成 [部署初始化](DEPLOYMENT.md) 后，脚本已生成 `/opt/mailhub/runtime/secrets/dingtalk.json`。在服务器本地编辑它，**不要把真实配置复制进仓库模板**：

```bash
sudoedit /opt/mailhub/runtime/secrets/dingtalk.json
sudo chown root:33 /opt/mailhub/runtime/secrets/dingtalk.json
sudo chmod 640 /opt/mailhub/runtime/secrets/dingtalk.json
```

下面是关闭状态的公开样例，不含可用凭据。填好真实参数和首批员工范围后，才把 `enabled` 改为 `true`；先保留通知关闭，免登与邮箱同步验证后再从控制台开启。

```json
{
  "enabled": false,
  "corp_id": "",
  "client_id": "",
  "client_secret": "",
  "agent_id": "",
  "allowed_userids": [],
  "allow_all_corporate_users": false,
  "notifications_enabled": false,
  "notification_digest_seconds": 0
}
```

`allowed_userids` 填企业管理员核对过的钉钉员工 **userId**，每项是字符串，不填姓名、手机号、邮箱、工号或 unionId。`allow_all_corporate_users=false` 且名单为空时，没有员工能通过本插件新建账号。确定开放全公司后才改为 `true`，同时调整钉钉可见范围；它不会允许匿名或其他企业人员注册。

检查 JSON 格式与必要参数，下列命令只输出结果，不输出配置内容：

```bash
sudo python3 - <<'PY'
import json
from pathlib import Path

p = Path('/opt/mailhub/runtime/secrets/dingtalk.json')
v = json.loads(p.read_text())
assert isinstance(v, dict), '配置必须是 JSON 对象'
assert type(v.get('enabled')) is bool, 'enabled 必须为 true 或 false'
assert type(v.get('allow_all_corporate_users')) is bool, '人员开关必须为布尔值'
ids = v.get('allowed_userids')
assert isinstance(ids, list) and all(isinstance(x, str) and x.strip() for x in ids), '员工名单格式有误'
if v['enabled']:
    assert all(isinstance(v.get(k), str) and v[k].strip()
               for k in ('corp_id', 'client_id', 'client_secret', 'agent_id')), '启用前须填写四类应用参数'
    assert v['agent_id'].isdigit() and int(v['agent_id']) > 0, 'AgentId 应为正数字符串'
    assert v['allow_all_corporate_users'] or ids, '启用前须指定试点名单或明确开放本企业人员'
print('配置格式检查通过；未输出密钥，尚未验证上游凭据。')
PY
```

保持 `secrets/` 父目录仅 root 可进入，不要为了让应用读取而开放整个目录。Compose 将这个文件单独只读挂载给 app/cron 容器，PHP 用户通过组 33 读取。文件属主和权限只是配置步骤之一，不代表上游凭据有效。

首次未启动的系统回到部署手册继续启动；已经启动的系统，修改后使用项目的安全重载流程，避免中断正在同步的任务，也确保原子替换后的文件挂载生效：

```bash
sudo bash /opt/mailhub/scripts/reload.sh
```

重载会短暂进入维护并等待当前后台任务结束，失败时按提示和 [维护手册](OPERATIONS.md) 处理，不要直接重启整台主机或全局 Docker。控制台保存的登录/通知偏好会覆盖 JSON 中同名的非秘密偏好；服务器 `enabled=false` 始终是主关闭开关。

### 2.6 发布给试点员工，再逐步开放

在应用的“应用发布 → 版本管理与发布”创建版本，选择本次网页能力与使用范围，先选 3–5 名试点员工，完成该企业要求的发布流程。只保存首页而没有发布，不能当作员工已经能使用。[官方发布说明](https://open.dingtalk.com/document/dingstart/publish-dingtalk-application)

钉钉可见范围控制工作台中的使用范围，服务器名单控制本插件是否接受员工身份，两层都要核对。按以下顺序试用：

1. 员工从正确企业的工作台进入，确认自己的身份与空白邮箱绑定页；管理员列表出现该员工。
2. 员工自行输入邮箱授权信息，分别测试发信、收信和附件；不要由管理员代收密码。
3. 员工在钉钉内设置网页登录密码，普通浏览器通过专属入口登录，看到同一组邮箱。
4. 管理员开启全局和试点员工提醒，确认基线建立后再发送新测试邮件；验证个人通知与打开位置。
5. 使用第二名员工验证相互隔离，执行本手册末尾的停用、恢复与会话验收。
6. 检查自然后台运行、额度、资源及备份，再扩大可见范围和服务器人员范围。

公司每位员工使用自己的账号，控制台不提供为全员统一绑定邮箱或绕过邮箱授权的功能。

### 高端口与内外网访问

电脑、手机和通知链接必须使用同一个完整地址，例如 `https://example.com:18443`。公司内部可以把该域名解析到内网地址，外部解析到公网地址；DNS 记录只保存地址，端口保留在访问 URL 中。

内网访问也要使用相同的 HTTPS 域名和端口。不要把内网 IP、HTTP 地址或另一套端口写进钉钉首页。证书验证的是域名；路由器映射、反向代理和登录跳转都需要保持正确端口。

高端口能在普通浏览器打开不等于钉钉各端已经验收。应分别测试公司 Wi-Fi 和手机蜂窝网络，检查首次登录、页面刷新、通知打开和附件操作。若配置钉钉服务器出口 IP 白名单，应填写服务器实际访问钉钉时使用的公网出口地址。

## 3. 看懂控制台状态

进入“公司邮箱管理”，点击“刷新状态”读取当前情况。

| 页面区域 | 含义和边界 |
| --- | --- |
| 钉钉应用 | 显示企业、应用标识、密钥是否存在、服务器开关和允许人员范围。“配置完整”检查必要字段存在，不会在线验证凭据有效，也不包含 AgentId 必然正确的保证。 |
| 服务状态 | 显示 Nextcloud/Mail 版本、维护模式、最近 cron、通知任务与扫描记录。任务时间更新只证明相应任务运行记录，不证明某封邮件已经同步或通知成功。 |
| 访问与通知 | 暂停新的钉钉登录，或启用、关闭个人新邮件摘要。 |
| 员工与绑定邮箱 | 显示通过本应用首次登录过的员工、邮箱地址、最近缓存同步、最近登录和访问状态。 |
| 通知任务与故障摘要 | 显示同步间隔、摘要窗口、队列数量、最近送达/失败及错误摘要。 |
| 运维入口 | 打开 Nextcloud 用户管理和服务器运行概览；不执行备份、恢复或证书更新。 |

“已映射员工”不是钉钉通讯录总人数。尚未首次登录的人不会出现在这里；“已绑定邮箱”是这些员工在 Mail 中添加的账号数量。一个人可以有多个邮箱。

“最近缓存同步”来自本地 Mail 记录，不是刚刚完成的连通性测试。显示了邮箱地址，也不保证授权仍然有效。

员工姓名来自本地账号显示名，并非持续同步的钉钉通讯录。当前没有自动同步姓名、部门或离职状态的功能；处理账号时结合列表中的钉钉用户标识核对身份。

控制台不展示邮箱密码、授权令牌、邮件主题、正文或附件。它会展示已绑定邮箱地址，因此只向工作所需的管理员开放。服务器及数据库管理权限属于更高权限范围，不应因网页不展示邮件就理解为管理员在技术上完全无法接触数据。

## 4. 控制登录与员工访问

不同开关的影响不要混淆：

| 操作 | 新的钉钉免登 | 已设置的普通网页登录 | 已有会话 | 个人通知 |
| --- | --- | --- | --- | --- |
| 关闭“允许新的钉钉登录” | 暂停。 | 不因此禁用。 | 不批量撤销；再次经过钉钉入口会先清理当前旧会话。 | 不自动关闭。 |
| 从服务器允许名单移除 | 后续验证不允许。 | 不因此禁用。 | 不等同于撤销所有令牌。 | 不再满足发送条件，已发出的请求不能撤回。 |
| 关闭全局或个人提醒 | 不影响。 | 不影响。 | 不影响。 | 停止后续提醒；重新开启不补历史。 |
| “停用并退出会话” | 拒绝。 | 拒绝。 | 撤销该员工认证令牌。 | 不再满足发送条件。 |

钉钉后台的应用可见范围变化不会直接停用 Nextcloud 本地账号。需要确定撤销员工访问时，使用最后一项，同时按公司流程处理原邮箱权限。

### 暂停新的钉钉登录

在“访问与通知”取消“允许新的钉钉登录”，点击“保存设置”。这适用于暂缓新登录或维护前控制入口。

这个开关本身不批量退出已经登录的员工，也不自动关闭通知。员工重新从钉钉入口打开时，会先执行安全退出旧会话，再显示登录暂停状态。需要暂停提醒时，还要关闭“启用个人新邮件摘要”；需要撤销某位员工访问时，使用该员工的停用操作。

服务器配置中的主开关关闭时，网页设置不能把它绕过。重新开启前，由服务器管理员确认配置和开放范围。

### 停用员工并退出会话

1. 在“员工与绑定邮箱”核对员工身份。
2. 点击“停用并退出会话”，阅读并确认提示。
3. 确认状态变为“已停用”。

此操作禁用该员工的 Nextcloud 账号，并撤销已有认证令牌。新的钉钉免登与普通账号密码登录都会失败，已有页面下一次需要服务器授权时不能继续访问；已经显示或下载到设备上的内容不会被远程擦除。

该员工将不再满足通知发送条件。已经提交给钉钉的消息可能仍然到达，本操作不能承诺撤回已提交通知。

控制台不能停用管理员或当前登录账号。它也不会停用原邮箱服务商账号、退出原邮箱网站或其他邮件客户端。

### 恢复员工

点击“启用账号”后，让员工从钉钉工作台重新打开。恢复账号不会恢复旧登录令牌，也不会绕过服务器允许人员范围、钉钉可见范围或邮箱授权要求。

### 人员离职

当前没有接入钉钉离职事件自动处理。离职时应主动停用本系统账号，同时按公司流程撤销原邮箱授权、调整钉钉应用可见范围及服务器允许人员范围。

仅从允许名单移除人员，可以阻止后续免登及通知，但不等同于撤销全部已有会话，也不会禁用员工已经设置的本地密码。要撤销两种入口的本系统访问，请执行“停用并退出会话”。

### 员工网页登录密码

员工从钉钉内进入个人设置 → 网页登录，可自行设置或重设独立密码，仍使用原来的映射账号和已绑定邮箱。管理员无需逐个分发初始密码，也不能在控制台查看员工密码。专属收藏链接只预填用户名，不是免密链接。

设置密码需要重新验证当前员工钉钉身份，成功后退出该账号所有旧会话。忘记密码仍可从钉钉重设；钉钉身份不可用时由管理员按企业身份核验流程处理。暂停钉钉免登开关不影响原生本地登录；离职务必停用账号并撤销会话。

本功能按当前无 Nextcloud 文件加密的部署验证。如果以后开启服务器端文件加密，本功能会拒绝无旧密码重设，应先按 Nextcloud 的密钥恢复流程处理。

处理员工“网页登录不上”的工单时，先确认输入的是个人页生成的网页用户名，而不是邮箱地址或钉钉手机号。员工可以收藏个人页提供的专属链接，省去反复输入较长用户名；链接只预填用户名，浏览器若已登录其他人，需要先退出。管理员不能在本控制台查看、导出或替全员统一发放员工密码。

不要为同一员工再手动创建一个普通账号，也不要手工修改映射表或把系统用户名改成邮箱地址。当前版本没有账号合并/别名管理流程，这样操作可能把邮箱配置留在另一个账号中。

## 5. 管理个人通知

### 开启或关闭

在“访问与通知”勾选“启用个人新邮件摘要”并保存，开启全局提醒。员工行中的“个人提醒”决定该员工是否接收，改变后点击“保存提醒”。同一设置重复保存不会重新建立通知起点。

通知实际发送还要求服务器主开关开启、应用配置有效、AgentId 可用、Mail 版本受支持、员工账号未停用且仍在允许范围内。单看一个勾选框不能判断这些条件全部成立。

应用发送的是给指定员工的个人工作通知，不是群机器人消息；每次发送只设置一个员工为接收人。内容只有新增邮件数量、应用链接和提醒时间，不传送邮件主题、正文或附件。

新版通知链接按设备区分：电脑使用本企业应用的工作区入口，手机使用钉钉内网页；两者均转到原免登入口，保留 HTTPS 高端口且不携带登录令牌。企业与应用标识由服务器配置提供，旧提醒不会自动改写。实际验证过的设备和版本见 [验收记录](VALIDATION.md)，本企业仍应分别验证计划使用的客户端。

当前控制台没有一键重发、补发历史、撤回通知或逐封查看通知对应邮件的功能。员工端也没有本插件的个人提醒设置页，需要管理员代为设置。

### 哪些邮件会提醒

通知模块读取 Mail 已完成同步的收件箱缓存。它不直接保持一条独立 IMAP 实时连接，邮箱尚未同步时就无法发现新邮件。

满足以下条件的新增邮件才进入摘要：收件箱名称为 INBOX，已完成本轮同步，邮件位于当前基线之后，且在扫描时未删除、不是草稿。新邮件即使已被其他客户端标记已读，也会计入；垃圾箱和其他文件夹不在这一规则内。仅改变已有邮件的已读状态不会重复通知；从其他文件夹移入 INBOX 后若获得新 UID，则可能被视为新增收件。

首次启用、关闭后重开、人员或邮箱映射改变、邮箱同步标识重置时，系统重新确定“从哪里开始”的基线，跳过此前邮件。开关或员工授权发生变化时，旧待发任务会按状态取消或停止自动处理；单纯邮箱同步标识重置不会统一撤销已排队摘要。已经被钉钉接受的任务不能因此撤回。此规则优先避免历史邮件集中补推，因此重新开启期间刚到达但已包含在新基线中的邮件，也可能不产生提醒。

### 延迟、数量与额度

后台按每分钟调度同步检查，每轮官方后台任务结束后立即追加通知扫描，将本次已经发现的新邮件按员工合并提交。默认 `notification_digest_seconds=0`，表示不再额外等待摘要窗口；支持 0–3600 秒，既有显式设置不会因升级自动改写，需要管理员核对运行配置和控制台实际值。原通知任务仍保留，与追加扫描共用互斥锁，避免两个入口同时处理同一批通知。

快速同步兼容层将已核对版本的同步任务就绪阈值设为 1 秒，实际触发计划仍是一分钟一轮；Nextcloud 每轮按任务 ID 防止重复执行。这个值用于避免任务顺序变化导致跳过下一轮，不代表每秒连接邮箱。自然同步频率仍需按每个账号连续观察，不能只凭 `cron` 最近时间更新判断全部邮箱都已同步。

这里的“立即”指本轮官方后台任务结束后的处理，没有额外设置一分钟等待；它不是每封邮件一到服务商就触发，也不是每个账号同步完毕时独立推送。等待下一轮检查、同轮其他任务、Mail 同步、队列、网络及钉钉接口仍会耗时，不能承诺 60 秒内到达。每次处理合并当前新增，不保证每分钟恰好一条通知；需要减少通知频率时，可由管理员显式增加摘要等待秒数。

“等待邮件数”是已经检测到、尚未合并进摘要的邮件事件数量，不包含已形成摘要中的邮件，也不是所有邮箱未读数量。状态区中的 `queue` 按摘要任务计数。“最近送达”是钉钉结果接口确认的投递记录，不是员工打开或阅读邮件的时间。

已被钉钉接受的摘要会独立查询结果，其回执未完成不会阻塞新收件形成下一批。发送期间发生停用或授权撤销时，迟到的结果不会把任务重新激活；已经发出的外部请求无法撤回，可能显示 `uncertain`，而不是承诺“已撤回”。

摘要减少了逐封通知的数量，但免登、获取令牌、发送通知和查询发送结果仍有接口调用。200 人试用扩大为全公司前，应在本企业钉钉后台核实实际调用额度、频率限制和相应费用政策，持续观察用量；不要用一条通知等于一次 API 调用估算。

每人绑定 1–2 个邮箱时，200 人对应约 200–400 个待检查账号；后台负载不能只按同时打开页面的人数估算。一分钟调度不代表这些账号能够同时完成同步，也不代表固定的连接次数。先用 3–5 人验证自然调度和真实投递，再逐步扩大，观察同步积压、任务耗时、提供商限流及主机资源。

### 通知状态对照

故障摘要保留接口中的英文状态名称，含义如下：

| 状态 | 中文含义 | 管理员如何处理 |
| --- | --- | --- |
| `queued` | 已形成待发送摘要，等待发送处理。 | 观察后台任务是否运行。默认没有额外合并等待；如显式配置了正数窗口，窗口内邮件还可能只是等待事件，未形成摘要。 |
| `sending` | 正在向钉钉提交，结果尚未记录。 | 短时出现正常；长期停留需检查后台任务和后续状态，不要直接重复发送。 |
| `submitted` | 钉钉接受了任务并返回编号，尚未确认目标员工投递结果。 | 等待结果查询；不能据此向员工确认“已经送达”。 |
| `delivered` | 钉钉结果接口确认该员工位于已读或未读接收名单。 | 表示接口确认投递，不证明员工已看见通知，也不证明读过邮件。 |
| `retry` | 明确失败或确认尚未提交，等待退避后重试。 | 检查错误摘要、网络和额度；系统会有限次数重试。 |
| `failed` | 确认失败、接收人无效/被禁止，或已达到重试上限。 | 核对应用权限、人员范围、配置和错误信息；当前没有后台手动重发按钮。 |
| `uncertain` | 提交或查询结果不确定，无法判断是否已经到达。 | 人工结合钉钉后台与员工实际收件情况核对；系统不自动重发，避免重复提醒。 |
| `cancelled` | 发送前人员、授权或通知设置变化，任务取消。 | 确认是否为预期的停用或设置变更；不会自动补发。 |

网络超时不一定代表发送失败。崩溃后发现已经处于提交中的任务、返回结果缺少必要字段、查询超过期限等情况，都可能归入 `uncertain`。不要通过反复开关通知试图重发，它会重建基线。

终态通知记录保留约 90 天，并由后台任务清理。通知队列不能替代邮件归档、审计平台或邮箱备份。

## 6. 邮箱接入与常见限制

员工操作流程见[员工手册](USER-GUIDE.md)。管理员应先允许服务商端的第三方客户端访问，并确认收信、发信分别可用。

当前插件会在 Mail 原有自动发现之前，优先按员工输入的真实邮箱域名及 MX 记录识别已知国内服务商。它只发现配置，不读取密码、不向多家服务商轮流尝试登录；匹配成功后仍由 Mail 的原有流程验证授权。未知或冲突的 MX 继续走原生发现，不保证所有自定义域名都能自动识别。

“正在查找配置”阶段发生在密码验证之前。若长期停留，应先检查应用容器使用的 DNS 是否能及时返回邮箱 MX，再检查外部自动发现地址的连通性。不要因此反复更换员工授权码。识别成功也不等于 IMAP、SMTP 已通过认证，仍需完成实际收发测试。

下表为当前控制台提供的常见配置，使用完整邮箱地址作为用户名；端口与加密方式必须配套。最终以企业租户及服务商当前要求为准。

| 邮箱类型 | IMAP 收信 | SMTP 发信 | 登录准备 |
| --- | --- | --- | --- |
| 腾讯企业邮箱 | `imap.exmail.qq.com`，993，SSL/TLS | `smtp.exmail.qq.com`，465，SSL/TLS | 开启客户端访问，按租户策略使用专用密码或授权码。 |
| 阿里企业邮箱 | `imap.qiye.aliyun.com`，993，SSL/TLS | `smtp.qiye.aliyun.com`，465，SSL/TLS | 管理员开启第三方客户端与 IMAP；启用安全密码时使用客户端安全密码。 |
| QQ 邮箱 | `imap.qq.com`，993，SSL/TLS | `smtp.qq.com`，465，SSL/TLS | 开启相应服务并使用授权码。 |
| 网易 163 / 126 / 企业邮箱 | 按具体产品的官方设置 | 按具体产品的官方设置 | 产品不同，地址和策略不同；开启服务并获取授权码。 |
| 其他自定义邮箱 | 服务商提供的 IMAP 地址、端口和加密方式 | 服务商提供的 SMTP 地址、端口和加密方式 | 确认允许第三方客户端且服务器能访问。 |

阿里邮箱的通用 SSL 端口与客户端权限要求见[阿里邮箱官方说明](https://help.aliyun.com/zh/document_detail/36576.html)。不要为了连接成功而关闭 TLS 证书验证。

仅支持 POP3、仅提供网页访问或没有授权给第三方客户端的邮箱，不在本方案通用 IMAP/SMTP 接入范围内。内网自建邮件服务器也需要单独审核访问设置；Nextcloud 默认限制访问本地地址作为远程服务，不应为方便接入任意放开限制。[Nextcloud Mail 管理说明](https://docs.nextcloud.com/server/stable/admin_manual/groupware/mail.html#local-imap-and-smtp-servers)

部门分发地址不一定有可登录的邮箱。如果它只是把邮件转发给成员，应让成员绑定自己的邮箱；共享邮箱只有在服务商支持且公司明确授权后才接入。更换客户端不会自动修复服务商反垃圾判断、群成员规则、退信或发信信誉问题。

### Gmail 单独验收

Gmail 不属于填写上述普通授权码后即可统一保证接入的项目。管理员需要为 Mail 配置 Google OAuth 客户端，设置与实际部署一致的完整 HTTPS 回调地址，再让每位员工完成授权。[Nextcloud Google OAuth 配置说明](https://docs.nextcloud.com/server/stable/admin_manual/groupware/mail.html#google-oauth)

Google 配置中的回调地址必须与实际请求一致，包括协议、域名、端口和路径；应从实际 Mail 配置获取，不要猜测路径。OAuth 项目的发布状态、用户范围和所申请权限可能影响正式使用，需要按 Google 后台提示处理。[Google 网页应用 OAuth 官方说明](https://developers.google.com/identity/protocols/oauth2/web-server)

Google 对嵌入浏览器授权有明确限制，不应通过伪装浏览器或跳过校验规避。需要在系统浏览器授权时，使用本项目已有的普通网页登录进入同一账号；不会把钉钉会话自动转交过去。[Google 安全浏览器政策](https://developers.google.com/identity/protocols/oauth2/policies#secure-browsers)

建议按以下顺序单独试用 Gmail：

1. 管理员在 Google 项目中准备网页应用 OAuth 客户端，并按项目类型确认用户范围、授权同意信息及适用的验证要求。
2. 按 Nextcloud Mail 管理说明，在管理设置的协作/Groupware 区域配置 Gmail 集成；确认回调使用本系统实际 HTTPS 地址，包括高端口，不猜测回调路径。
3. 员工先在钉钉内设置自己的 Mailhub 网页登录密码。
4. 员工在普通浏览器打开自己的专属入口，用网页用户名和该密码登录；确认看到原来的账号和邮箱。
5. 在这个浏览器的 Mail 中添加 Google 邮箱，完成 Google 授权；Google 密码只在 Google 授权页面处理。
6. 分别验证收信、发信、后续后台同步、钉钉中的已有邮箱访问及提醒，再决定是否开放给其他人。

这是一条需要在本企业验证的接入路线，不是 Gmail 已完成统一验收的声明。客户端到 Google 登录页、服务器到 OAuth 和邮件服务的网络都要分别可用；授权后撤销或过期也需要重新处理。

## 7. 按现象排查

| 现象 | 检查顺序 |
| --- | --- |
| 钉钉找不到应用 | 企业组织是否正确、应用是否发布、员工是否在可见范围。 |
| 首页能开但免登失败 | 实际首页与免登域名配置、钉钉版本、企业/应用参数、服务器出口限制、服务器允许人员、错误发生时间。不要收集员工授权码。 |
| 显示暂未开放 | 服务器主开关、钉钉登录开关、配置文件可读性和必要参数。 |
| 员工未出现在后台 | 是否已经首次成功免登；是否查看了正确企业的映射。 |
| 邮箱绑定失败 | 服务商客户端权限、IMAP/SMTP 开关、完整用户名、授权码、地址端口及服务器出站连通性。 |
| 收发异常但钉钉登录正常 | 优先检查邮箱授权和 Mail 同步；这属于不同连接链路。 |
| 有邮件但无提醒 | 是否在 INBOX、是否已删除或草稿、是否为基线之前邮件、Mail 是否同步完成、全局及个人开关、人员状态、后台任务、队列状态。已读状态本身不排除新增邮件。 |
| `submitted` 长时间未结束 | 结果查询是否正常、钉钉接口额度、后台任务是否持续运行；不能仅依据任务编号判断送达。 |
| `uncertain` | 核对钉钉平台记录和实际接收情况；不自动重发，不反复切换开关。 |
| 页面显示无法读取状态 | 管理员会话是否失效、是否仍有管理员权限、服务是否在维护；重新登录后刷新。 |
| 只有外网或只有内网失败 | 分别检查 DNS、入口端口、NAT、证书和登录跳转地址；手机蜂窝网络与公司网络分别测试。 |

排查材料只保留必要的时间、员工标识、设备版本和错误码。日志与截图不应包含邮箱密码、应用密钥、授权令牌或客户邮件内容。

## 8. 运维和升级

### 建议的日常检查

| 时机 | 关注事项 | 处理入口 |
| --- | --- | --- |
| 每个工作日 | 后台任务时间是否推进、通知错误、员工反馈的收发异常。 | 本控制台与维护手册中的只读诊断。 |
| 定期 | 证书期限和续期任务、磁盘增长、备份最新成功记录、接口额度。 | [维护手册](OPERATIONS.md)；“定时器已安装”不等于最近一次运行成功。 |
| 新员工加入 | 钉钉可见范围与服务器允许范围，员工首次免登和自行绑定。 | 第 2、4 节。 |
| 员工离职 | 停用并撤销本系统会话，同时处理原邮箱及钉钉权限。 | 第 4 节；不等待尚未实现的离职事件。 |
| 修改密钥/配置 | 核对受限文件权限，按安全重载流程等待后台工作结束。 | 第 2.5 节和维护手册。 |
| 升级、迁移或故障恢复前 | 可恢复备份、固定版本、兼容限制、维护窗口与回退方案。 | 先阅读维护手册，不直接替换正在使用的镜像或数据库。 |

定期确认后台任务时间持续更新，观察磁盘容量、证书有效期、服务异常和通知错误。Nextcloud 运行概览中的建议应由服务器管理员结合部署配置处理。

备份应包含数据库、Nextcloud 配置及数据、账号映射与运行配置；备份中的凭据需要同等保护。控制台没有备份恢复按钮，也不能证明备份可恢复，需按部署文档在隔离位置实际演练。

仅安装证书续期任务不代表备份已启用。备份需另一个文件系统上的实际挂载位置，再按维护手册安装和检查备份任务；不要把同盘目录当作独立备份设备。

部署脚本默认关闭 Nextcloud 首次使用介绍与版本新功能弹窗（`firstrunwizard`），员工第一次进入直接绑定邮箱；安全更新检查保留。需要恢复介绍时，由服务器管理员按维护流程处理并同步调整部署脚本，避免下次启动重新关闭。

本次目标版本为 Nextcloud 34.0.5 / Mail 5.12.5。免登适配代码当前仅允许 Nextcloud 34；通知读取当前 Mail 的数据结构，只允许 5.12.4 和 5.12.5；每分钟同步适配则仅对 Nextcloud 34 / Mail 5.12.5 生效。更换主版本或 Mail 版本会触发兼容性限制，应先审核适配、备份，再在测试环境完成下节验收，并单独核对自然同步频率。不要仅因应用商店显示可更新就直接升级生产环境。

## 9. 上线验收记录

下面是待执行的验收项目，不是已通过记录。逐项记下日期、设备、测试人员、结果及异常处理后再决定开放范围。

- [ ] 公司内网、外网分别验证 HTTPS、高端口和跳转地址，电脑与手机均无证书错误。
- [ ] 两名员工分别从钉钉免登，刷新后仍可操作，A 无法访问 B 的邮箱及附件。
- [ ] 同一设备切换钉钉员工后重新进入，先完成安全登录准备、退出旧会话；随后 SDK 加载失败、取码失败或登录暂停，都不保留上一个员工的可用登录。安全准备本身失败应明确报错，不当作退出成功。
- [ ] 普通浏览器打开钉钉入口不会自动注销已登录的本地管理员；未经页面安全校验的请求不能强制退出会话。
- [ ] 未在允许范围的员工、停用员工无法建立新的会话；未登录访客和普通员工无法使用管理接口。
- [ ] 停用后旧会话不能继续访问服务器数据；重新启用后需重新登录；独立本地管理员入口仍可用。
- [ ] 员工从钉钉设置网页登录密码，在普通浏览器登录同一账号并看到同一组邮箱；专属链接不含密码，已登录另一账号时不会悄悄切换身份。
- [ ] 员工更换密码后旧密码和旧会话失效，新密码与后续钉钉免登可用；停用员工后，两种登录入口均被拒绝。
- [ ] 每种准备开放的邮箱分别验证授权、发信、收信、回复、附件及客户端间同步。
- [ ] 首次开启通知不推历史；基线建立后新邮件按规则形成摘要，并在目标员工钉钉中实际收到。另测一封先被其他客户端标记已读的新邮件，以及已有邮件反复切换已读状态不重复提醒。
- [ ] 新邮件提醒只发给对应员工，内容没有主题、正文或附件；通知链接进入当前员工的邮箱。
- [ ] 关闭、重新开启和停用行为符合规则；`submitted`、`delivered`、`uncertain` 在操作记录中没有混淆。
- [ ] Gmail 如需开放，单独完成真实 OAuth、持续收发和所用钉钉设备的授权流程验收。
- [ ] 备份恢复演练完成，并确认恢复后的账号映射、邮箱配置和通知基线行为。

验收通过后再扩展钉钉可见范围及服务器允许人员范围，并把[员工手册](USER-GUIDE.md)发给使用人员。
